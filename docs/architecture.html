Factory Inventory Management System

A full-stack demo: a Vue 3 single-page app talks to a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

Data flow

How a filter change on the dashboard becomes new numbers on screen.

  1. A user changes Time Period, Warehouse, Category or Order Status in FilterBar. These four refs live in useFilters at module scope, so every view shares the same state.
  2. The active view has a watch on those refs. It builds a filter object and calls api.js, which drops any value equal to all and sends the rest as query parameters.
  3. The FastAPI route receives the parameters and runs apply_filters() (warehouse, category, status) and filter_by_month() (month or quarter, matched against order_date) over the in-memory lists.
  4. The route returns either filtered records or an aggregate, such as inventory value, low-stock count and pending orders from /api/dashboard/summary. Pydantic models validate the response shape.
  5. The view stores the raw response in refs such as allOrders and inventoryItems. Computed properties derive chart series, status breakdowns and top products, so the UI updates without extra fetches.

Findings worth knowing

Observed while reading the code. Each one affects how you extend the system.

Client calls endpoints the server does not define.

api.js includes /tasks (GET, POST, PATCH, DELETE) and /purchase-orders (POST, GET by backlog item), but main.py has no matching routes. The Pydantic models PurchaseOrder and CreatePurchaseOrderRequest exist, and purchase orders are only read as a flag on /api/backlog. Features that depend on these calls will fail with a 404.

State is ephemeral by design.

Data loads once at server start and nothing writes back. Restarting resets everything, and a future write path needs a persistence decision before it needs code.

The API base URL is hard-coded.

http://localhost:8001/api is a constant in api.js, and CORS allows every origin. Fine for a local demo; both need configuration before any shared deployment. .env.example is empty.

A Backlog view exists but is not routed.

views/Backlog.vue is not registered in main.js; backlog data appears on the Dashboard through a detail modal instead. The user and task data in useAuth is mocked client-side.
